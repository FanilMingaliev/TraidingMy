# ScalpRadar

Сайт и Android-приложение, которые отвечают на два вопроса: **когда входить в сделку** и **что делать
с уже открытой** — держать, фиксировать часть или закрывать. Работают без своего сервера: данные берутся
с публичных API бирж (Bybit → Binance → OKX) прямо в браузере или в приложении.

Приложение ордера не выставляет — сделки вы открываете и закрываете сами на бирже.

## Что на экране

- **Сигналы.** Состояние рынка, «форма» сетапа, карточки «ВОЙТИ» с готовым планом (вход, стоп, две цели,
  объём под ваш риск) и список наблюдения с полосой «сколько осталось до сигнала».
- **Мои сделки.** После кнопки «Я вошёл в сделку» приложение сопровождает позицию и крупно пишет, что делать:
  ДЕРЖАТЬ, ЗАФИКСИРОВАТЬ 50 % или ЗАКРЫТЬ — с причиной, результатом в R, процентах и деньгах, шкалой
  «стоп — вход — цели». Закрытые сделки уходят в историю с личной статистикой.
- **Настройки.** Депозит, риск на сделку, плечо, монеты, частота обновления, уведомления, демо-сигнал,
  необязательное подключение своего сервера.

Данные обновляются сами (по умолчанию раз в минуту), пока приложение открыто на экране. О новом входе и о
моменте, когда сделку пора фиксировать или закрывать, приходит уведомление со звуком.

## Алгоритм и насколько ему можно верить

### Что проверено

Прежний алгоритм (общий счёт 15 индикаторов, вход при счёте ≥ 45) перепроверен на свежих данных:
8 недель, 10 монет, 1068 сделок — **−119R**, в плюсе 42 % сделок. Корреляция счёта с будущим движением
цены на горизонте 1–4 часа около нуля или отрицательная на всех трёх проверочных отрезках. Поэтому как
сигнал на вход он отключён и оставлен справкой в разборе монеты (в настройках его можно включить для
наблюдения).

Вместо него искался сетап, который переживает проверку на данных, не участвовавших в подборе. Из
проверенного (тренд, импульс, RSI, объёмы, положение в суточном диапазоне, контекст биткоина, шорт после
разгона) след оставил один — **«Отскок после пролива»**:

- вход в лонг, когда цена за час упала на **3 и более часовых ATR**;
- стоп — **2 часовых ATR** (с узким стопом цену выбивает до отскока — это видно по всей сетке вариантов);
- цели — **1R (50 %)** и **1.5R (50 %)**, выход по времени через **4 часа**;
- объём позиции считается от риска в деньгах, поэтому широкий стоп риск не увеличивает.

### Честный результат

`npm run validate`: 10 монет, 720 дней до 02.10.2026, комиссия 0,1 % за круг.

| Период | Сделок | В плюс | Средняя | Итог |
|---|---|---|---|---|
| Последние 6 месяцев, все сигналы | 194 | 66 % | +0.24R | +46.6R |
| Предыдущие 18 месяцев, все сигналы | 673 | 42 % | −0.18R | −119R |
| 2 года, все сигналы | 867 | 48 % | −0.08R | −72.4R |
| 2 года, с фильтром формы | 281 | 55 % | +0.03R | +9.5R |

**Устойчивого преимущества нет.** Сетап зарабатывал в последние полгода (и на других 21 монете за тот же
период тоже), а в предыдущие полтора года терял: в падающем рынке проливы продолжаются, а не отскакивают.
Простые фильтры тренда эти периоды не разделяют.

Поэтому работает **фильтр формы**: приложение само проигрывает сетап на последних 30 днях по всем монетам
и выдаёт вход, только если за это время он в плюсе (и набралось не меньше 10 сделок). На двух годах это
сократило убыток с −72R до примерно нуля — то есть фильтр убирает худшие периоды, но прибыльной стратегию
не делает. Год, на котором фильтр не настраивался, с ним тоже остался в минусе (67 сделок, −21R), просто
меньшем, чем без него (247 сделок, −42R).

Правила досрочного выхода «по развороту индикаторов» тоже проверены (`npm run exits`) и результат не
улучшили — сделка закрывается по стопу, целям или времени.

Практический вывод: это инструмент дисциплины (план, размер позиции, стоп, момент выхода, учёт
результата), а не источник гарантированной прибыли. Разумно начинать с минимального объёма и сверяться с
собственной статистикой на вкладке «Мои сделки».

## Запуск

```bash
npm install
```

Сайт в режиме разработки (http://localhost:5173):

```bash
npm run dev:web
```

Сборка сайта в `web/dist` — это обычная статика, её можно положить на любой хостинг:

```bash
npm run build
```

В репозитории есть workflow `.github/workflows/pages.yml`: после включения GitHub Pages
(Settings → Pages → Source: GitHub Actions) сайт публикуется при каждом пуше в `master`.

## Android-приложение

Готовый файл — `dist-apk/ScalpRadar.apk` (отладочная сборка). Скиньте его на телефон, откройте и разрешите
установку из этого источника. Сервер и компьютер для работы не нужны — только интернет.

Пересборка после изменений (нужен Android Studio с SDK):

```bash
npm run apk
```

Готовый APK появляется в `android/app/build/outputs/apk/debug/app-debug.apk`.

Ограничение: рынок отслеживается, пока приложение на экране (экран при этом не гаснет). В свёрнутом виде
Android останавливает обновления, и уведомления не приходят.

## Свой сервер (необязательно)

Сервер добавляет то, чего нельзя сделать в браузере: новостной фон (RSS) и разбор монеты ИИ — ключ
`ANTHROPIC_API_KEY` хранится только на сервере. Мнение ИИ справочное и на сигнал не влияет.

```bash
cp .env.example .env
```

```bash
npm run dev
```

В приложении: Настройки → «Работать через сервер» → адрес сервера (и токен, если задан `API_TOKEN`).
Сервер также ведёт журнал выданных сигналов (`GET /api/journal`): локально в `data/journal` или в Supabase,
если заданы `SUPABASE_URL` и `SUPABASE_SERVICE_KEY`.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ANTHROPIC_API_KEY` | ключ для разбора ИИ | — (ИИ отключён) |
| `AI_MODEL` | модель Claude | `claude-opus-5` |
| `PORT` | порт сервера | `8787` |
| `API_TOKEN` | токен доступа к API при публикации наружу | — |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | журнал сигналов в облаке | — (локальные файлы) |

## Устройство проекта

```
core/     Движок, общий для сайта, приложения и сервера (чистый JS, работает в браузере и в Node)
  setups.js     сетап «Отскок после пролива»: условие входа
  replay.js     проигрывание сетапа по истории, фильтр формы
  health.js     форма сетапа за последние недели — считается прямо в приложении
  position.js   сопровождение открытой сделки: держать / фиксировать / закрывать
  simulate.js   проигрывание одной сделки по барам (общий код бэктеста и журнала)
  analysis.js   индикаторы, факторы, план сделки, оценка риска
  scan.js       сканирование списка монет и итоговое решение
  market.js, derivatives.js   данные бирж с автопереключением источников
web/      React + Vite + Tailwind: интерфейс; собирается в сайт и в Android-приложение (Capacitor)
server/   Необязательный бэкенд (Express): новости, ИИ, журнал сигналов, проверка на истории
android/  Проект Capacitor для сборки APK
```

## Проверка на истории

```bash
npm run validate
```

Двухлетняя проверка сетапа тем же кодом, что работает в приложении (`core/replay.js`). Первый запуск
скачивает историю свечей (до часа), дальше она берётся из `data/research`.

```bash
npm run exits -- --days 14
```

Правила досрочного выхода для прежнего алгоритма.

`server/scripts/research/` — шаги исследования по порядку: диагностика прежнего алгоритма, корреляция
факторов с будущим движением, квантили признаков, сетки параметров, проверка на отложенном периоде и на
других монетах, разбор по режимам рынка, фильтр формы. `npm run backtest`, `calibrate`, `regimes` —
инструменты для прежнего алгоритма.

## Ограничения

- Доходность не подтверждена — см. таблицу выше.
- Расчёт не учитывает проскальзывание и стакан; во время пролива спред шире обычного. При комиссии
  с проскальзыванием 0,2 % за круг результат последних шести месяцев падает с +0.24R до +0.17R на сделку.
- Сигналы только в лонг; в спокойном рынке их может не быть днями.
- Приложение не выставляет ордера и не является инвестиционной рекомендацией.
